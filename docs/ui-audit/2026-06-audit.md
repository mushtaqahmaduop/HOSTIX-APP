## 3. PKR PKR Regression Check

**Status: NO BUG FOUND**

The codebase uses two currency formatting patterns correctly:

1. **`<span class="pkr">PKR</span>${fmtNum(value)}`** — for stat-card values
   - `.pkr` CSS class provides size/weight styling only (no `::before` pseudo-element)
   - `fmtNum()` returns number only (no "PKR" prefix)
   - Result: `PKR 19,000` (correct)

2. **`${fmtPKR(value)}`** — for inline text/sublines
   - `fmtPKR()` returns `"PKR " + formatted number`
   - Never wrapped in a `.pkr` span
   - Result: `PKR 19,000` (correct)

No collision between these two patterns exists. No CSS `::before { content: "PKR" }` pseudo-element found.

## 4. Key Findings & Diagnosis

### 4.1 Color discipline violations (from strategy doc)

| Issue                              | Status    | Evidence                          |
|------------------------------------|-----------|-----------------------------------|
| Money is colored                   | **Fixed** | Quick Win 7.1 applied (this session) |
| Rainbow stat-card icons            | Present   | Each card class has unique icon bg |
| Status pills all compete           | Present   | 5+ badge colors on reports screen |
| Headers glow                       | **Fixed** | Quick Win 7.2 applied (this session) |
| Multiple accents fighting          | Present   | Gold sidebar + teal/red/blue cards |
| Dark mode over-saturated           | Present   | Same colors, no desaturation      |
| Inline styles dominate             | Present   | 1,774 `style=""` attributes in JS |
| Hex literals bypass token system   | Present   | 142 unique hex colors in JS alone |

### 4.2 The three worst offender patterns

1. **PDF generation templates** (`students.js`, `reports.js`) — Entire HTML documents built with hardcoded hex colors. These can't use CSS variables because they render in separate contexts (BrowserWindow/print). Phase 4 should standardize a shared PDF stylesheet.

2. **Inline `style=""` on every element** — 1,774 inline styles across JS modules. The dashboard alone has 426. These override any CSS class system and make theme switching fragile.

3. **10+ semantic colors where 4 would suffice** — green, teal, blue, royal, purple, gold, amber, red, plus their `-dim` variants. The token system needs to collapse these to: success (green), warning (amber), danger (red), info (blue), and one accent (violet/royal).
